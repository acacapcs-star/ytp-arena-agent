## 比賽性質

與一般 IOI / Codeforces 型的解題競賽不同，這是 **AI Agent 對戰策略遊戲**：
兩隊各自實作一個自主決策的 Agent，在四個固定場景中兩兩對戰，搶奪場上的寶箱。
沒有標準答案，勝負取決於策略設計與持續迭代。

**計分規則**：每場比賽勝隊得 1 分，**平手雙方皆不得分**，依總積分排名。
這條規則直接決定了策略方向——保守求穩沒有價值，必須算清楚哪些寶箱搶得到、
哪些該直接放棄，把資源集中在能贏的那幾顆上。

**團隊**：靈機一動.cpp — 藍宥欣（隊長）、謝宜宸、星焰

**成績**：初賽 23/99 → LCQ 復活賽 **2/35**（晉級 Top 15）→ 進入決賽。

賽制為每日循環賽，系統每晚十二點抓取各隊提交、跑一次完整對戰，隔日九點更新計分板。
因此開發節奏是「每天改一版、隔天看結果」——本專案的參數大多是這樣調出來的。

## 核心設計

Agent 每個 tick 要決定一件事：**現在該往哪個方向加速。**

這個決定拆成四層：

```
場景辨識 → 候選篩選 → 路線規劃（beam search）→ 控制修正（MPC）
```

### 一、場景辨識

`_update_scenario_profile()`

四張地圖的障礙物配置與雙方出生點是固定的，因此可在開局第一個 tick
以**障礙物數量 + 雙方起始座標**判斷當前是哪一張，之後切換整套參數：

| Profile | 判斷條件 | 特性 |
|---|---|---|
| `open` | 障礙物 0 個 | 空曠，純競速 |
| `trap` | 15 個 + 起點 (5,5) / (95,95) | 障礙密集，需繞行 |
| `gravity_seed1` | ≥18 個 + 特定起點 | 有重力場 |
| `gravity_seed7` | ≥18 個 + 另一組起點 | 有重力場，配置不同 |
| `generic` | 以上皆非 | 保守通用參數 |

**這是針對固定地圖的調校，不是通用解。** 換一張沒見過的地圖，Agent 會落回
`generic` 模式，表現會明顯下降。這個限制是刻意接受的取捨——賽制中地圖固定，
針對性調校的邊際效益遠高於通用性。

### 二、候選篩選

完整模擬每一顆寶箱的成本太高，因此先用**閉式解快速估計 ETA**（`_estimate_eta_fast`），
依加速度與最高速限制推算抵達時間，取前 K 名進入下一階段。

另外保留兩類額外候選：

- **群聚候選**：本身 ETA 不是最好，但「附近還有下一顆」，連吃的總收益可能更高
- **路線記憶候選**：上一輪規劃過的目標，避免每 tick 反覆改變主意

### 三、路線規劃

`_choose_rollout_next_targets()` · `_simulate_plan()`

以 **beam search** 展開「接下來要吃哪幾顆、依什麼順序」，最多模擬 4 顆、
beam width 4（殘局擴大到 8）。每條路線都跑一次物理模擬，計算實際的抵達時間序列，
再以折現後的總收益評分。

規劃時同時考慮對手：

- `_simulate_opponent_captures()` — 模擬對手接下來會吃到哪些寶箱
- `_predict_opponent_path()` — 預測對手的移動軌跡
- **競速懲罰** — 若對手比我早到，該寶箱的分數大幅折減
- **阻擋加成** — 若我能在對手抵達前先拿走，額外加分

換言之，Agent 不只在算自己最快的路線，也在算**哪些寶箱搶得到、哪些該放棄**。

### 四、控制修正

`_mpc_refine_acceleration()`

規劃層給出目標點後，控制層再做一次短視距的 MPC：列舉數個候選加速度
（直衝、煞車、左右偏移等），各自向前模擬數步，選擇綜合表現最好的一個。

這一層處理的是規劃層看不到的東西：牆面反彈、障礙物碰撞、重力場拉扯造成的偏移。

## 開發過程中的取捨

**114 個常數，全部是實測調出來的。** 檔案開頭的參數區塊是這個專案最大的部分，
每一個都對應一次「改了、隔天看計分板、留下或改回來」的循環。

幾個記錄下來的判斷：

- **`MIN_COMMIT_TICKS`（選定目標後至少維持幾 tick）**——早期版本每 tick 都重新規劃，
  結果 Agent 在兩顆寶箱之間反覆搖擺、兩顆都沒吃到。加上最短承諾時間後才穩定。
- **重力場地圖的對手模擬 dt 放大 5 倍**（`OPPONENT_SIM_DT_MULTIPLIER_SEED1`）——
  重力場中對手軌跡變化大，細算沒有意義，粗估反而更穩且省時間。
- **殘局切換精確模式**（`ENDGAME_EXACT_ENABLED`）——剩餘寶箱少於門檻時，
  beam width 加大、模擬時距拉長，因為此時每一顆的權重都很高。
- **`SCORE_PRESSURE_*` 一組參數**——落後時提高冒險傾向，領先時偏保守。

## 已知限制

- **場景辨識依賴固定地圖。** 未見過的配置會落回 generic 模式。
- **參數是針對特定對手池調出來的。** 循環賽的對手固定，因此部分權重（尤其是阻擋與競速懲罰）
  可能過擬合當時的對手行為。
- **對手模型假設對手是理性的最短路徑追逐者。** 面對刻意干擾或非理性打法時預測會失準。
- **沒有學習成分。** 全部是規則與搜尋，不含任何訓練過的模型。
