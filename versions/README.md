# 版本演進

這個資料夾保留了比賽期間的中間版本。最終送交的是根目錄的 `strategy.py`（3,022 行），
但那是從八個獨立的小模組一路長出來的——過程本身比結果更能說明我們怎麼工作。

---

## 演進路徑

```
八個情境各自獨立實作（38–84 行的小模組）
        ↓ 合併
01_merged        1,329 行 ·  23 個參數
        ↓ 加入 beam search、MPC、對手模擬、殘局模式
02_beam_mpc      1,779 行 ·  44 個參數
        ↓ 加入路線記憶
03_route_memory  1,940 行 ·  59 個參數
        ↓ 加入場景辨識
04_scenario      2,135 行 ·  62 個參數
        ↓ 重構精簡
05_refactor      2,116 行 ·  62 個參數
        ↓ 大量參數調校
strategy.py      3,022 行 · 114 個參數
```

---

## 各階段做了什麼

### `00_modules/` — 情境拆解階段

對應[策略設計文件](../docs/strategy-design.md)裡的八個基本情境，每個先獨立寫成小模組：

| 檔案 | 行數 | 對應情境 |
|---|---|---|
| `acceleration.py` | 64 | **E** 加速度控制——正規化方向、煞車距離 `v²/(2a)` |
| `nearby_chest.py` | 84 | **F** 附近有寶箱——多目標順序與路徑選擇 |
| `planet_enemy.py` | 50 | **A** 行星引力 + **B** 對手追蹤 |

`nearby_chest.py` 開頭有 `from acceleration import acceleration_control`——
模組之間已經在互相呼叫，不是各寫各的。

**這個階段的價值在於：每個情境都先想清楚、寫出來、能單獨測試，才進到合併。**

### `01_merged_1329.py` — 第一版整合

把獨立模組合成單一 `Strategy` 類別。已經有「快速初選 + 撞牆路線 + 多寶箱滾動模擬」的
基本骨架，但只有 23 個參數，決策仍以貪心為主。

### `02_beam_mpc_1779.py` — 策略成型的那一步

**跨度最大的一次改版**：1,329 → 1,779 行，參數 23 → 44。一口氣加入四樣東西：

- **beam search** 多寶箱路線規劃
- **MPC** 加速度修正
- **對手捕獲模擬**
- **殘局模式**

在此之前 Agent 是「選一顆最近的衝過去」；在此之後它開始規劃「接下來吃哪幾顆、
什麼順序、對手會不會先拿走」。

### `03_route_memory_1940.py` — 解決搖擺問題

加入路線記憶（`ROUTE_MEMORY_*`）。

早期版本每 tick 都重新規劃，結果 Agent 在兩顆寶箱之間反覆改變主意、兩顆都沒吃到。
路線記憶讓上一輪選定的目標保有加成，配合 `MIN_COMMIT_TICKS` 才穩定下來。

### `04_scenario_2135.py` — 針對地圖調校

加入場景辨識（`PROFILE_*`）。發現四張地圖的障礙物配置與出生點固定，
可以在開局第一個 tick 判斷是哪一張，然後切換整套參數。

**這是一個明確的取捨**：換來針對性的表現，代價是失去通用性。
賽制中地圖固定，所以這筆划算。

### `05_refactor_2116.py` — 往回收的一步

2,135 → **2,116 行，少了 19 行**，參數維持 62 個。

這一版沒有加任何功能，是把重複的邏輯收乾淨。保留它是因為——
**不是每一步都該是加東西。**

### `../strategy.py` — 最終版

3,022 行、114 個參數。相較 `05_refactor` 增加的部分主要是：

- 各場景的專屬處理函式（`_trap_left_bait_target`、`_seed1_top_left_cleanup_target` 等）
- 對手阻擋（blocking）與碰撞預測
- 殘局精確模式
- 分數壓力調節（落後時提高冒險傾向）

**參數從 62 增加到 114，幾乎全部來自實測。** 賽制是每日循環賽——晚上十二點抓取提交、
隔天早上九點更新計分板——所以開發節奏就是「改一版、隔天看結果、留下或改回來」。

## 怎麼讀這些檔案

想看**演算法怎麼從貪心變成搜尋**：比較 `01` 與 `02`。

想看**參數是怎麼長出來的**：比較各版本開頭的參數區塊。

想看**一個功能完整的實作**：直接讀根目錄的 `strategy.py`。
