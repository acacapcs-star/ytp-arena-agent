# 策略設計：從八個情境到一支 Agent

這份文件記錄的是比賽期間的策略拆解過程。最終送交的 `strategy.py` 是這個過程的結果，
但拆解本身在程式碼裡看不到，因此保留下來。

**團隊「靈機一動.cpp」**：藍宥欣（隊長）、謝宜宸、星焰

## 拆解方法

比賽場上同時存在多個互相影響的因素。與其一次面對全部，先把它們拆成**八個獨立情境**，
各自想清楚該怎麼應對，再處理兩兩組合、四個組合，最後合成一套決策流程。

```
8 個基本情境 → 28 組兩兩組合 → 關鍵四四組合 → 全合的 act()
```

## 八個基本情境

### A｜有行星（Planet）

行星會產生引力場。**引力大小為 100/r**——半徑越小的行星引力越大，越危險。

- 偵測自己是否在引力範圍內
- 在範圍內則主動補償反向加速度

### B｜有對手（Opponent）

- **追蹤對手位置**：每 tick 記錄，存前兩個 tick 推算速度
- **EMA 平滑**：`avg_delta = α·delta + (1-α)·avg_delta`，N=12（可調 9–15），α = 2/(N+1)
- **估算對手 ETA**：`opp_eta = opp_d / opp_speed_toward`；速度為 0 時設極大值
- **穩定接近判定**：速度變化量在平均值 50–60% 以內
- **優先選我比對手近的寶箱**：`my_eta < opp_eta` 時大幅加分
- **對手很遠**（`opp_d > L × 0.3`）→ 純貪心，不管對手
- **對手很近**（`opp_d ≤ L × 0.1`）→ 選對手到不了的寶箱
- 過渡區間平滑切換，避免船在兩種模式間亂跑

### C｜兩行星引力抵銷（Gravity Cancel）

**關鍵發現：這題的引力是開關式的**——進入範圍才有，與距離無關。
因此不存在真正的引力平衡點，原本「找平衡點懸停」的構想不成立。

改為尋找**安全走廊**：

- 偵測兩個行星範圍是否重疊：`dist(obs1, obs2) < r1 + r2`
- 引力大小接近才算有效：`|100/r1 − 100/r2| < 5.0`
- 走廊中心＝兩圓心中點，`safety = 1/(|g1−g2| + 0.1)`
- 寶箱靠近走廊時加分
- 在 `initialize` 預先算好，不必每 tick 重算

### D｜靠近牆（Wall Bounce）

- **動態 margin**：`margin = max(4.0, v²/(2·max_accel))`，只看垂直牆面的速度分量
- **不強制轉向**：偵測連續 N frame 朝牆（N=3）才介入，慢慢把垂直分量減小
- **角落雙重保護**：`dist_corner = √(dist_x² + dist_y²)`，推離方向 `n = dist/dist_corner`，
  離哪面牆近，那個方向的力自然更大
- **靠牆行進時**：垂直分量歸零，平行分量保留

### E｜加速度控制（Acceleration）

每 tick 只能給一個 `[ax, ay]`。

- 正規化方向向量
- **煞車距離 = v²/(2·max_accel)**
- 距離 > 煞車距離 → 全力衝；距離 ≤ 煞車距離 → 反向煞車
- 多個力疊加時注意 `max_accel` 上限

### F｜附近有寶箱（Nearby Chest）

- `dist ≤ chest_radius + ship_radius` → 已捕獲
- 距離 < 5 → 放棄煞車，全力衝（寶箱半徑夠大）
- **多目標路徑**：掃描 `L×0.15` 範圍內所有寶箱
  - 排成一線 → 直接衝過去順路拿
  - 分散但不遠 → S 型路徑
  - 太分散 → 迴轉選最近的
  - 目標是總時間最短，不要東跑西跑

### G｜行星當誘餌（Obstacle Decoy）

行星不只是障礙，也可以是武器。

- 故意繞行星邊緣走，讓對手跟著我的路徑被引力吸走
- **小半徑行星引力大，更適合當陷阱**
- 在對手與寶箱之間佈置「引力陷阱路徑」

### H｜對手搶同一顆（Contention）

- 我更近 → 全力衝
- 對手更近 → 放棄，換下一個
- **距離相當時看 player_id**：同 tick 捕獲時 player 0 獲勝，
  所以 player 0 繼續搶，player 1 換目標或提前一 tick 到位

## 兩兩組合（節錄）

28 組全部討論過，以下是實際寫進最終版本的幾組。

**AB｜行星 + 對手**——對手在引力範圍內會被拉偏。我繞開行星走直線，對手走彎路。

**AE｜行星 + 加速度**——引力是額外的加速度，必須納入計算。補償引力後剩下的才用來衝寶箱；
若補償已用掉全部 `max_accel`，暫時放棄該區域。

**AF｜行星 + 附近有寶箱**——進入角度要算好，**讓引力幫你加速衝向寶箱**，拿完立刻反向逃出。

**BD｜對手 + 牆壁**——對手撞牆後速度反轉會短暫失控，趁那個瞬間搶寶箱。

**BE｜對手 + 加速度**——對手速度快但有慣性會衝過頭。我慢速精準到達，或衝向他路線前方卡位。

**BF｜對手 + 附近有寶箱**——兩顆寶箱都很近時各拿一個，不要搶同一顆。

**DE｜牆壁 + 加速度**——平行分量保留，垂直分量減到零。不要讓垂直速度累積。

**DF｜牆壁 + 附近有寶箱**——沿牆切入減少撞牆風險，拿完立刻往場地中心加速，不在牆邊滯留。

**EF｜加速度 + 附近有寶箱**——距離 < 煞車距離開始煞車，距離 < 5 放棄煞車直接衝。

**GH｜誘餌 + 搶同一顆**——故意往行星方向衝，對手以為我放棄而全力衝寶箱，我再急轉回來。

## 關鍵四四組合

**ABEF｜行星 + 對手 + 加速度 + 附近寶箱**

最常見的實戰情況，也是 `act()` 的主要邏輯：

```
1. 對手距離 → 算壓力場
2. 引力補償計算
3. 煞車距離判斷
4. 綜合評分選寶箱
```

**ABGH｜行星 + 對手 + 誘餌 + 搶同一顆**——偵測到與對手搶同一顆時，
判斷行星位置，故意走行星旁邊誘敵，對手被吸偏我先到。

**CDEF｜引力走廊 + 牆壁 + 加速度 + 附近寶箱**——複雜地形下以走廊為中繼，
控制垂直牆面速度，精準煞車後從安全角度切入。

**BDGH｜對手 + 牆壁 + 誘餌 + 搶同一顆**——把對手引向牆壁與行星之間的死角，
對手撞牆失控加上被引力拉扯，我趁機拿。

## 執行限制

三個必須遵守的硬限制，直接決定了演算法能有多重：

- **`move_timeout`：每 tick 只有 1 秒** —— 演算法不能太慢
- **`game_time_budget`：全場只有 60 秒思考時間** —— 這是總預算，不是每 tick
- **引力是進入範圍才有**，不是全場都有 —— 這一點推翻了原本的平衡點構想

這也是為什麼最終版本要做候選預篩（閉式解快速估 ETA）、限制 beam 寬度與模擬深度，
並在殘局才切換到高成本的精確模式。
